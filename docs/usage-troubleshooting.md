# 使用步骤与故障排查

## 使用步骤

### 1. 被控手机端设置
- 被控手机手动连上 WiFi
- 安装接收端 APK，点开 APP，前台服务启动，顶部出现常驻通知
- 查看被控手机局域网 IP 地址（设置 → WLAN → 点击已连接网络查看）

### 2. 手表控制端设置
- 手表（7.1.1）连同一个路由器 WiFi
- 安装控制端 APK，填入上面拿到的被控 IP

### 3. 操作
- 点【开启警报】：被控手机最大音量播放警报 + 持续振动
- 点【关闭警报】：停止

## 已知故障点（实际调试一定会碰到）

### 4. 路由器 AP 隔离
- **现象**：手表与手机互相收不到 UDP 包
- **解决**：需要关闭路由器 AP 隔离功能（进入路由器管理后台查找相关设置）

### 5. 系统杀掉前台 Service
- **现象**：被控手机休眠一段时间，系统杀掉前台 Service → 收不到指令
- **解决**：重新点开被控 APP 重启服务
- **进阶**：root 可以调 `oom_score_adj` 缓解，无 root 只能手动
- **建议**：在手机系统设置中给该 APP 开启「自启动」「后台运行」「无限制」等权限

### 6. 被控 WiFi 断开
- **现象**：WiFi 断开后无法通信
- **处理**：APP 会自动跳 WiFi 设置页，需要你手动点开 WiFi

### 7. 防火墙 / 安全软件拦截
- **现象**：UDP 8888 端口被直接丢包
- **解决**：关闭手机防火墙或安全软件，或将该 APP 加入白名单

## 调试小技巧

先在电脑上用 netcat 测试 UDP 端口通不通，确认网络没问题，再调试安卓 APP。

### 测试 UDP 链路是否通畅

**在被控端电脑上监听（模拟接收端）：**
```bash
nc -u -l 8888
```

**在控制端电脑上发送（模拟发送端）：**
```bash
echo "ALARM_ON" | nc -u <被控端IP> 8888
```

如果监听端能收到 `ALARM_ON`，说明网络链路正常，问题在 APP 层；如果收不到，说明是网络/防火墙/AP隔离问题。

---

## 注意事项

- 端口固定 8888，同一 WiFi 局域网内生效，外网无效
- 前台服务通知不能去掉，否则高版本安卓直接杀死 Service
- 警报音频文件 `alert.wav` 需放到接收端 `res/raw/` 目录下
- 被控手机 WiFi 需手动提前打开，APP 不做自动开 WiFi
